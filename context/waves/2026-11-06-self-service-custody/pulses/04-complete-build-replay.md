## Publication gate implementation

Current CI checks out exact PR/default source, independently replays complete
source/runtime and retains raw qualification logs. A separate default-only job
downloads the same runtime/source artifacts, verifies full Git/source/input/
provenance/grant identities and current default commit, then publishes a uniquely
named commit release. Existing tags never move and existing assets never clobber.
Only a matching draft may receive missing assets; all assets must verify before
publication. Published metadata/tag and every complete binary are read back
anonymously before the job emits the source commit that permits Pages deployment.
Historical matching releases can be verified without publishing or replacing them.

Fourteen publication state-machine test methods cover matching draft resume,
published idempotency, read-only behavior, conflicting tags/body/assets, default
advance, missing digest fallback, complete anonymous bytes, metadata corruption,
byte bounds and credential-free HTTPS redirects. Actual c03 full-archive/runtime
and hosted source/API preflight passes without mutations. An actual anonymous
11,451,273-byte pinned bindgen SDK release download verifies redirect/stream/hash
handling; this is an external SDK test, not a TAXLANE source publication.
The updated actual full local input check also verifies runtime provenance and
every original source/runtime grant. Actual authenticated SDK asset API binary
streaming fallback returns the same pinned complete bytes; its source-verifier
hash is retained in pulse04-publisher. No TAXLANE release is created by these tests.
